# Pocket Engineer 0.3.0-rc1 — offline workbench preview

[Open on Render](https://pocket-engineer.onrender.com/) · [Test history](https://github.com/MuhammadTahaBinZaeem/FOP-Project/blob/main/docs/TEST_HISTORY.md) · [Actual Android screenshots and measured limits](https://github.com/MuhammadTahaBinZaeem/FOP-Project/blob/main/docs/UI_ANDROID_STRESS.md)

This is a **prerelease**, not a production-signed mobile/store release. It implements 55 explicitly bounded topic families, not every possible problem in an engineering course. All mathematics, classification and solution-step generation run in C++. Maintained runtime source is 81.91% C++; including HTML/CSS in that denominator gives 72.78%. Tests, generators, archives and generated/vendor code are excluded from both figures.

## Choose your download

| Asset | How to use it |
| --- | --- |
| `PocketEngineer-0.3.0-android-debug.apk` | Android API 24+ with an updated System WebView. Install the development-signed APK. Bundles native C++ and interface; no INTERNET permission or initial website download is needed. |
| `PocketEngineer-0.3.0-Windows-x64.zip` | Extract; run `bin/pocket-engineer-server.exe`; open the printed loopback address in a browser. Keep the server running. |
| `PocketEngineer-0.3.0-macOS-universal.zip` | Extract; run `bin/pocket-engineer-server` from Terminal; open the printed address. Universal Intel/Apple Silicon build, deployment target macOS 11. |
| `PocketEngineer-0.3.0-Linux-x64.zip` | Extract; run `bin/pocket-engineer-server`; open the printed address. The Ubuntu-built binaries require glibc 2.38+ and libstdc++ providing GLIBCXX_3.4.31. Not a static all-distribution binary. |
| `PocketEngineer-0.3.0-offline-website.zip` | Complete static website with WASM. Serve the extracted directory on localhost or HTTPS; do not double-click `index.html` with `file://`. Alternatively, install the live website after it says “Ready offline.” |

Desktop executables are not code-signed/notarized; OS security warnings may apply. Do not disable system-wide security protections. CI debug signing keys are not a stable production update identity: a future APK may not update this one in place. Export important solutions before changing installations; uninstalling clears app-local history. An unsigned release APK is deliberately not advertised as an installable download.

The downloaded Ubuntu native executable does **not** launch unmodified on this NixOS host because its generic ELF loader is unavailable; that observed failure is not called a pass. NixOS users can install the website/PWA or build the C++ source in their native development environment, as was done for the local engine tests. Do not treat the Linux ZIP as an AppImage or musl-static bundle.

`SHA256SUMS.txt` covers the attached assets and `BUILD_SOURCE.txt`. Packages are copied unchanged from the tested workflow artifacts; only their outer filenames are clarified. To serve the website ZIP with the included native server, pass a port and the absolute extracted website path: `pocket-engineer-server 8080 /path/to/website` (quote paths containing spaces).

The APK is 8,587,630 bytes; the complete website ZIP is 326,354 bytes. Checksums and ZIP integrity were checked before publication. Android SDK signature verification (v2) and 4 KB ZIP alignment checks passed, and the APK installed and ran locally. This does not certify 16 KB-page Android devices or production signing.

## Changes

- Responsive flat-color interface, corrected mobile insets and bottom navigation, readable system-bar icons, wrapping labels and 44px touch controls.
- Original generated raster logo; 1.8 KB header mark. Critical offline website approximately 746 KB including the C++ WASM engine. Original large PNG artwork is excluded from app bundles; the debug APK was reduced by approximately 49% relative to the earlier build.
- Numbered solution steps, method-check evidence, bounded local history, copy, JSON export, native Android print preview and offline reload.
- Responsive charts draw at measured CSS size with capped pixel density; K-maps use native HTML tables. No SVG assets.
- Input/recursion/iteration limits, worker timeouts, loopback server validation and bounded browser WASM memory.

## Evidence and limitations

The source commit for these binaries is `de21cf40125d358717250568af123ad7696b6e7e`. Package workflow [33990843529](https://github.com/MuhammadTahaBinZaeem/FOP-Project/actions/runs/33990843529) **passed** Windows, macOS, Linux and both Android instrumentation tests. Website workflow [33990843528](https://github.com/MuhammadTahaBinZaeem/FOP-Project/actions/runs/33990843528) **passed all 28 browser tests**. The full local run also passed 28/28 with 800 UI endurance solves, and four checks passed against the live Render site. Later documentation commits do not silently change these binaries.

Recorded development evidence includes 1,606,929 independent/edge checks with zero failures, 825,000 same-engine snapshot matches (not independent mathematical proof), sanitizer checks and 800 browser UI endurance solves. Local offline APK runs matched 160 independently expected arithmetic answers across three runs and completed all 55 topic examples. Native keyboard/touch behavior, document saving, print preview and Android rotation were also exercised; not every action was tested on a physical phone.

The final downloadable APK was separately installed and run offline here: all 55 topic examples plus another 10/10 expected arithmetic answers passed, with zero page errors. The corrected chart was asserted and visually inspected in the actual Android WebView. Total recorded local arithmetic comparisons across the four runs are 170, not 170 distinct curriculum families.

Remaining performance concern: host-rendered debug emulator runs reported approximately 32–33% janky frames; software rendering was worse. UI timing includes automation and scrolling, and app PSS excludes renderer/system overhead. Physical low-memory ARM phones, OEM WebView variants, production signing, OS PWA installation and universal curriculum coverage are not certified by these results. Historical failures and their fixes remain visible in the test history.
