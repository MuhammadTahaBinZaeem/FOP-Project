# Pocket Engineer 0.5.0-rc1 — offline visual engineering labs

Access correction: this repository is private, so these GitHub-hosted assets require repository access. Authenticated CI execution did not establish anonymous download availability. A corrective rc2 uses public Render file delivery while preserving source privacy.

[Open on Render](https://pocket-engineer.onrender.com/) · [Test history](https://github.com/MuhammadTahaBinZaeem/FOP-Project/blob/main/docs/TEST_HISTORY.md)

This preview adds clickable 2–6 variable K-maps, matrix-cell input, a circuit drawing grid, DC/AC/transient network analysis, state-machine tables and diagrams, and thirteen signals/transform tools. The shared C++ engine performs the calculations and validation. [Supported methods and limits](https://github.com/MuhammadTahaBinZaeem/FOP-Project/blob/main/docs/ENGINEERING_LABS_V5.md) are explicit; this is not an unrestricted symbolic mathematics or SPICE implementation.

The offline demo browser includes 825,000 stored cases: 55 original problem types × three difficulties × 5,000. Select category, problem type and difficulty; calibrate this device, test a page or the whole set, cancel, and export expected/actual comparisons. Stored snapshots are regression checks, not independent mathematical proof. The new engineering labs have separate independent tests and runnable presets, not an additional 5,000 stored cases for every operation.

## Offline access and downloads

Visit the Render site while connected and wait for **Ready offline**. **Prepare / repair offline access** verifies the app, solver and every demo bank. Then the same URL works in the same browser without networking. Installing the PWA is optional; a first-ever offline visit, cleared storage, private browsing or cache eviction cannot retain an installation that is not there. Complete cached assets are approximately 9.2 MB, with a 1.25 MB critical bundle.

| Package | How to run |
| --- | --- |
| `PocketEngineer-0.5.0-android-preview.apk` | Android 7+ with an updated System WebView. Optimized, non-debuggable, development-signed Release APK. All UI, demo files and native C++ are bundled; no INTERNET permission. |
| `PocketEngineer-0.5.0-Windows-x64.zip` | Extract everything; open `Start-Pocket-Engineer.cmd`. |
| `PocketEngineer-0.5.0-macOS-universal.zip` | macOS 11+, Intel or Apple Silicon. Extract everything; open `Start-Pocket-Engineer.command`. |
| `PocketEngineer-0.5.0-Linux-x64.zip` | x86-64 Linux. Extract everything; run `sh Start-Pocket-Engineer.sh`. C/C++ runtime is statically linked, including for NixOS. |
| `PocketEngineer-0.5.0-offline-website.zip` | Complete WASM website for localhost or HTTPS hosting. Do not double-click `index.html`; use a desktop ZIP for a ready-to-launch local application. |

Desktop launchers open a loopback-only local website; keep their terminal running. No Python, Node, account or internet connection is required. If the browser does not open automatically, use the address printed by the launcher. `SHA256SUMS.txt` and `BUILD_SOURCE.txt` identify the exact package bytes and source.

Android preview signing certificates can differ between builds. Export important history before replacing an incompatible certificate: uninstalling removes app-local history. A stable owner-controlled production key remains required. Windows executables are unsigned and macOS executables are not notarized; do not disable system-wide security protections.

- [Website CI 34698199078](https://github.com/MuhammadTahaBinZaeem/FOP-Project/actions/runs/34698199078): **80/80** browser tests across desktop and phone layouts, including breakpoint label sizing, offline repair, all 165 bank names, stale CDN generations and the thirteen signal forms. The downloaded website separately passes all 80 tests through the downloaded Linux launcher on NixOS.
- Local validation: all five Release CTest suites and all five ASan/UBSan suites pass. Original independent stress: 1,606,929 checks with zero failures. Original stored corpus: 825,000 matching answers and verification labels. Workbench: 23,374 checks; additional engineering studies: 31,941 checks, including analytic randomized RC comparisons.
- The Ubuntu-built Linux ZIP runs unmodified on NixOS from a path with spaces. CLI, local HTTP server, natural interpretation, circuit/signal extension and bundled demo manifest pass. macOS CI executes Apple Silicon; both architecture slices are built, but this is not an Intel Mac execution test.
- The real Render URL passed a fresh persistent-browser restart with all networking disabled on September 12: natural determinant input, convolution and 5,000 hard stored comparisons all succeed.
- Every original demo bank was run through actual offline UI controls: **825,000 cases, zero snapshot mismatches**. The optional `PocketEngineer-0.5.0-demo-comparisons.tar.gz` contains all per-case expected/actual exports plus a per-bank report and a separate audit against the hashed bank bytes. These are regression comparisons, not independent mathematical proof.
- The final downloaded Release APK passes all four local instrumentation tests in **44.413 seconds** with radios disabled. Three emulator scrolling runs report **5.96%, 5.02%, 11.49%** native jank. A separate display trace reports median/p95 frame spacing of **16.765/24.625 ms**, with longer stalls and gesture gaps retained. These are emulator observations, not established physical-phone smoothness or zero lag.

Actual APK testing discovered and repaired Android's transformed `.gz` asset filenames and worker file-fetch restriction. Banks now use `.pebank`, packaged bytes are checked inside the APK, and Android transfers compressed bytes to the data worker. The every-bank UI replay also caught a filename check rejecting the digit in RK4; it now accepts valid digit-bearing names while rejecting unsafe paths. Bounded C++ batches reduce bridge overhead while preserving cancellation and expected/actual values. CDN image recompression also broke strict offline hashes; a hashed original-image archive fixes this without weakening validation.

Maintained production runtime source is 82.12% C++; including HTML and CSS, 77.10%. Both gates run in CI. Tests, generated corpora, documentation, archives, vendor and generated glue are excluded consistently. Numerical work and decompression run away from the UI thread, with explicit input/work limits, bounded output tables and no continuous animation loop.

Physical low-end phone testing, stable production signing and 16 KB Android runtime-device testing remain open. Emulator frame measurements are evidence for that emulator and journey, not proof of universal 60 FPS or zero lag. Final package, downloaded-file and frame-measurement results are recorded in the test history after execution.
