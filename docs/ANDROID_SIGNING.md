# Android release signing

Release builds are not automatically production-signed. Android requires a
consistent private signing key for ordinary in-place updates; keep a secure,
recoverable backup under the project owner's control. See the
[official signing guide](https://developer.android.com/studio/publish/app-signing).

Supported GitHub Actions secrets:

- `PE_ANDROID_KEYSTORE_BASE64`: base64-encoded project keystore.
- `PE_ANDROID_STORE_PASSWORD`: keystore password.
- `PE_ANDROID_KEY_ALIAS`: signing alias.
- `PE_ANDROID_KEY_PASSWORD`: key password.

CI restores the keystore only under its temporary directory, exports the signing
environment to Gradle, and uploads only APKs and non-secret signing-status text.
Never commit the keystore, its base64 encoding, or passwords. A keystore is not
generated by the build, preventing accidental changes in the update identity.

Without configured secrets, CI's explicit `PE_ALLOW_DEVELOPMENT_SIGNATURE=true`
produces an installable, optimized release preview using its ephemeral debug key.
The publication helper names this `android-preview.apk`, not a production release.
It is non-debuggable but still development-signed. The separate debug artifact is
for diagnostics only. A default local release build without either setting stays
unsigned so an unsigned APK cannot be mistaken for an installable release.

Older previews may have different certificates. Export important solutions
before switching; Android can require uninstalling an old differently signed
preview, which removes its app-local history. Production signing does not confer
Google Play publication, physical-device coverage, or guaranteed OS compatibility.
